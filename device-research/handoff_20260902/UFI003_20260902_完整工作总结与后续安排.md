## 4. IMS/MCFG 的核心实验结论

### 4.1 已实锤 MCFG 控制 IMS QMI 服务发布

本 MPSS 内已有六个 software MCFG，包括：

- `ROW_Generic_3GPP`
- `Commercial-Airtel`
- `Commercial-CSFB-SS-CU`
- `Commercial-SRLTE-SS-CT`
- `Commercial-CSFB-SS-CMCC`
- `Commercial-Reliance`

无 SIM 时，将内置 `Commercial-Reliance` 设为 selected 并 activate，基带重启后立即新增：

```text
ims  (1.0)  -> service 0x12，IMSS / IMS Settings
imsa (1.0)  -> service 0x1e
imsp (1.0)  -> service 0x1f
```

因此可以排除：

- MPSS build 完全裁剪掉 IMS 服务端
- 必须先有 Android IMS userspace daemon 才会发布这些服务
- 必须插入有效 SIM 才能发布服务

最强结论是：PDC/MCFG 的激活状态直接决定 MPSS 是否注册这些 QMI server。

### 4.2 插入联通卡后的新发现

插入联通卡后，基带启动期自动选择：

```text
Commercial-CSFB-SS-CU
Version: 0x2011550
ID: BA:D1:41:DA:65:46:19:33:22:B4:08:AB:CE:C9:1A:F2:8A:32:3C:89
```

该 profile 激活时不发布 IMSS/IMSA/IMSP。

在联通卡仍插入的情况下，手动 Set Selected + Activate `Commercial-Reliance`：

- 基带按预期重启
- Reliance 没有保持 active
- 启动完成后 CU profile 立即重新成为 active
- IMS 三服务仍缺失
- SIM 始终保持 `present / ready`

结论：SIM/运营商信息参与 MPSS 启动期 MCFG autoselect；联通卡会把 runtime 配置拉回 CU。SIM 不是直接创建或关闭 IMS 服务，而是通过选择 MCFG 间接影响服务发布。

### 4.3 userspace 能做什么、不能做什么

Userspace 可以：

- 通过 PDC Get/List 查询 profile
- Set Selected 某个已有 profile
- Activate profile，使 modem 子系统重启

Userspace 不能：

- 凭空创建 MPSS 内不存在的 QMI server
- 在 CU MCFG 明确不发布 IMS 服务时，仅靠启动 `imsqmidaemon` 或 `imsdatadaemon` 把 server 变出来

今天的 Reliance A/B 证明：userspace 的作用是触发 PDC 选择；真正注册 IMSS/IMSA/IMSP 的是 modem/MPSS。

## 5. 当前启动钩子状态

第二根棒子已安装：

- `/etc/systemd/system/ufi003-reliance-mcfg.service`


```bash
sudo systemctl enable ufi003-reliance-mcfg.service
```

是否禁用应先由用户确认，因为它会改变无卡时自动发布 IMS 服务的实验行为。

### 阶段 B：建立“正确内核 + 联通卡”的稳定基线


不要并发运行多条 qmicli，也不要把 endpoint hangup 误判成硬件故障。

3. 搜索与本机 `DPM.2.0.2 / M8936FAAAANUZM` schema 匹配的真正中国联通 VoLTE MCFG。
4. 候选优先顺序：中国联通 VoLTE > China Mobile > T-Mobile > Jio/Reliance。
5. 外部 MCFG 加载属于新的 modem 配置写入实验；必须先备份、核对 schema，并再次获得用户确认。

在不写卡、不发短信、不打电话的前提下，可进行：

## 9. 下一步最值得验证的一个假设

> MPSS 在 UIM ready 后根据 SIM 的 MCC/MNC 自动激活 `Commercial-CSFB-SS-CU`；该 autoselect 的优先级高于当前 userspace 启动钩子的 Reliance Set Selected/Activate。若找到关闭 autoselect 的开关，或加载同 schema 的联通 VoLTE MCFG，IMSS/IMSA/IMSP 就可能在联通卡存在时持续发布。

理由：

- 无卡 + Reliance：IMS 三服务出现
- 有联通卡 + CU：IMS 三服务消失
- 有联通卡强制 Reliance：modem 重启后立即回 CU
- 正确 kernel/DT 只修复 SIM 物理/板级访问，并未改变上述 MCFG 行为
